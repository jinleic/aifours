## 2. Exact generation and completeness argument, conditional on source correctness and completion

For fixed `n`, the source lists every nonempty row bit mask of cardinality at least two in increasing integer order. It depth-first generates **nondecreasing** `n`-tuples of these masks. A candidate row is intersected with the precomputed compatibility sets of every already chosen row, excluding precisely those that would have a singleton row intersection; the inclusive suffix allows repeated rows. Thus every admissible row multiset is generated once, and no admissible multiset is lost. At each accepted leaf, the separate multiset-permutation generator yields each distinct ordering exactly once. Every labeled matrix has one unique sorted row multiset and one of those distinct orderings. Fixed column bits represent the original `n` distinct labeled columns, so this produces each labeled mask exactly once rather than merely an isomorphism representative.

The remaining pruning is necessary, not a heuristic or a twin assumption. At a prefix, `available` is an over-approximation of all rows any valid completion can next use: it enforces only sortedness and compatibility with the existing prefix. Each prefix column signature records exactly which selected rows contain that column. The code rejects only when:

1. no row remains available;
2. the number of edges still needed is smaller than the sum of all current column-degree deficits to two;
3. the remaining edge count is outside the interval obtained by multiplying the smallest/largest available row weights by the number of remaining rows;
4. some column cannot reach degree two even if every remaining row contains it, or still needs an incidence but no available row contains it; or
5. two columns already overlap in exactly one selected row and **no** available future row contains both. Their unique overlap could otherwise never be increased to at least two.

The child edge bound uses only the universal future row weights between two and `n`. These tests cannot reject a valid completion: every future row of such a completion is in the current availability superset. At leaves, the code independently checks exact excess, both degree conditions, both singleton-overlap conditions, and connectivity before emitting a record. The control suite is not a substitute for this argument or for parent source audit.

## 3. Additional twin-isolation filter and its boundary

This stage is computed only after the graph predicate accepts. It tests on both sides that the two opposite neighbors of every degree-two line have degree at least three, and that the neighbor pairs of distinct degree-two lines are pairwise disjoint. The Boolean is named `twin_necessary`; graph-only masks rejected here are still emitted, with `false`.

For an actual unitary support component of order greater than two, a degree-two row with neighbors `a,b` forces columns `a,b` to have identical row neighborhoods: every other row must meet the degree-two row in zero or both positions, never one. If their common degree were two, those two orthonormal columns would form a two-dimensional unitary on their two rows and exhaust those rows, isolating an order-two block. Two degree-two rows cannot share exactly one neighbor by the graph rule; if they share both, their orthonormal two-entry rows form a unitary on those two columns and exhaust them, again isolating an order-two block. Transposition proves the column version. This is an extra actual-unitary necessity; the graph-only overlap rule is not by itself the isolation premise.
