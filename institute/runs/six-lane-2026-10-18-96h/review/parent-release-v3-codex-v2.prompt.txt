1119: def _hash_file(txn, parent, name, path, selected):
1120:     _require(selected['bytes'] <= MAX_LATE_FILE_BYTES, 'late regular file cap16GiB')
1121:     _require(txn.streamed_bytes + selected['bytes'] <= MAX_LATE_HASH_BYTES, 'late aggregate hash cap128GiB')
1122:     fd = txn.open(name, os.O_RDONLY | FILE_FLAGS, parent=parent, display=path)
1123:     try:
1124:         before = txn.native('fstat ' + path, os.fstat, fd)
1125:         actual = _metadata(before)
1126:         _require(actual['kind'] == 'file' and _exact(actual, selected), 'late file lstat/open inode or metadata mismatch')
1127:         txn.must_tick('late regular file initial identity')
1128:         digest, seen = hashlib.sha256(), 0
1129:         while True:
1130:             block = txn.native('read ' + path, os.read, fd, min(CHUNK, selected['bytes'] + 1 - seen),
1131:                                retain=txn.stream)
1132:             seen += len(block)
1133:             digest.update(block)
1134:             _require(seen <= selected['bytes'], 'late file grew during read')
1135:             if not block:
1136:                 break
1137:         after = txn.native('fstat ' + path, os.fstat, fd)
1138:         txn.must_tick('late regular file final identity')
1139:         _require(seen == selected['bytes'] and _stat_key(before) == _stat_key(after), 'late file identity/size/metadata changed')
1140:         result = dict(actual)
1141:         result['sha256'] = digest.hexdigest()
1142:         txn.hashed_files += 1
1143:         return result
1144:     finally:
1145:         txn.close(fd, 'P5_LATE_CENSUS_INCOMPLETE')

ACK re-reads exact length via parent `read_bytes`, original deadline checked on success/Exception, compares exact bytes and hash, then lstat under retained directory fd must match original dev/ino/size, regular/nlink1; completion deadline checked again. Failure=>ACK_FAILED (successful-but-late read=>ACK_UNPROVED_DEADLINE); **no registry line**. Successful readback does not waive a failed deadline/close.

After ACK_OK only: registry is opened anchored O_RDWR|O_APPEND|NOFOLLOW|NONBLOCK, **no O_CREAT**; must be regular one-link positive inode, <=16MiB. Selected observed prefix length/SHA must persist; new suffix must be complete JSON lines; any same-item suffix must be v2 HELD for same allocation, else refuse. Parent must serialize writers: this is compare-and-append under a **single-writer premise**, not a lock-based multiwriter algorithm. Bounded write of one LF-terminated sorted-key JSON row, fsync, size check, clean FD/directory closes, then final ORIGINAL deadline check.

Row format `parent-release-registry-v2`: item, state RELEASED|HELD, disposition path/SHA, allocation_line_sha256, decision_in_disposition, ordered causes, recorded_at (owned text/null), reservation, remaining_output_reservation_bytes (0 only proposed RELEASED), release_effect warning. On normal HELD with safe ACK/current registry, one HELD line. If no safe selected allocation/registry or deadline is gone, no unsafe append; caller receives HELD/uncertainty. A partial append, fsync/close failure, concurrent growth or final-deadline crossing can leave line bytes visible: caller MUST retain reservation HELD. Never erase/fix a torn line in place.

Result `parent-release-result-v2`: state HELD by default; decision (on-disk proposal), release_effective bool, ack status, disposition path/SHA/bytes/create-progress/fsync/identity, registry status/state/hash/bytes/fsync/closed/progress, ordered causes/evidence/parts, original_deadline_crossed, bounded callback events/digest, FD counts/unresolved, uncertainty and external boundary statements. `decision:RELEASED` is **not** result.state RELEASED. Only complete caller-observed returned state RELEASED is eligible for CP1 release integration.

## v3 mechanisms (source anchors are function:lines in v3)

**F1 — final assembled result check.** In `decide_and_commit` (`1648-1701`), the complete returned dict is first assembled by `_final` (`1687`).    For example, a disposition write can return after the original deadline, followed by fsync and readback before the deadline is inspected. A late first pread can be followed by more preads. These paths violate checkpoint002’s checks after every blocking step, including a safe HELD fallback.

   The eventual aggregate check generally prevents completed release after detected lateness, but it does not prevent the intervening I/O.

   **Minimal repair:** Thread the transaction through these helpers and check the original predicate after each blocking completion, including Exception paths. Preserve the primary native failure and secondary deadline failure separately. After detection, permit only cleanup of already-owned resources.

3. **MAJOR — Directory iterators lack protected acquisition and unresolved-resource reporting.**  
   **Locations:** `_names:822`, `_names:823`, `_names:829`.

   `os.scandir(fd)` acquires an iterator without an immediately preceding deadline check or a registered ownership record. A preceding fstat can complete late and still be followed by iterator acquisition. Enumeration and its closing fstat also run without intermediate completion checks.

   Iterator-close failure is not represented in `txn.unresolved` or the descriptor/resource report. If enumeration first fails and `iterator.close()` then raises, the normally returned HELD report records only the outer exception description; the primary survives temporarily in exception context but is not retained in that bounded report.

   Consequently, `fds.live == 0` and an empty unresolved sample do not establish complete module resource closure.

   **Minimal repair:** Protect iterator acquisition with the original predicate, retain ownership before subsequent checks, and record unresolved iterator closure explicitly. Attempt at most one owning close and retain both enumeration and cleanup failures.

4. **MAJOR — A registry close BaseException skips cleanup of another owned descriptor.**  
   **Location:** `_append_registry:1453`, particularly the close at **1454** before the directory close at **1456**.

   If `txn.close(fd, ...)` raises a non-Exception BaseException, execution exits the `finally` block before closing `dfd`. `_Txn.close` has already recorded the first descriptor’s uncertain close, but the independently owned directory descriptor remains live. Commit propagation then bypasses normal result construction.

   This path remains HELD, but it leaves an acquired resource without its owning close attempt and without the normal attached resource report.

   **Minimal repair:** Use nested cleanup protection so each already-owned descriptor receives at most one close attempt even if the first close raises. Preserve the primary and secondary exceptions, propagate afterward, and preserve all partial files or registry bytes.

5. **MAJOR — Artifact validation failure disables an existing commit-directory exclusion.**  
   **Locations:** `_v_artifacts:507`, `_shape:639`.

   The prohibition against `commit_dir == artifacts.job_dir` runs only when the entire artifacts object survived validation.

   Concrete case: supply a valid job-directory path, an artifact exceeding CAP, and that same directory as `commit_dir`. `_v_artifacts` refuses the map, so `ctx.f['artifacts']` is absent. The exclusion is skipped, and the later HELD transaction can create its disposition inside the artifact directory.

   HELD prevents resource release, but it does not justify bypassing the explicit destination restriction or modifying that publication namespace.

   **Minimal repair:** Validate and retain the job-directory path independently, and apply the existing exclusion even when another artifact field fails validation.

6. **MINOR — Root insertion bypasses the global tree-entry cap.**  
   **Locations:** `_walk:1114`, `_scan:1071`.

   `_scan` checks `MAX_TREE_ENTRIES` after adding child entries. `_walk` inserts each root without that check. If the first root produces exactly 200,000 entries, a subsequent empty, nonoverlapping root produces 200,001 entries without triggering another child insertion.

   The main checker can therefore complete fresh accounting above the documented cap. Its decision contains summaries rather than the full fresh manifest, so decision serialization does not necessarily reject this case.

   **Minimal repair:** Apply the same global entry-count check immediately after inserting every root.
