## 3. DH389 — exact computational task, old lower bounds and a current reduction

**Book statement/page.** Printed389–390 defines CDH on a prime-order cyclic group G=<g>: given g,g^a,g^b for random a,b in Z_q, output g^(ab) with non-negligible probability by a probabilistic polynomial-time machine. It separately defines DDH and several oracle variants. This is not unconditional qPKE with quantum public states. Classical computational security, decision distinguishability, a reduction using a CDH oracle, and an actual CDH solver are different goals.

**Formal target if selected.** Fix an efficiently constructed family of uniquely encoded prime-order cyclic groups and a CLASSICAL operation/access model. For every sufficiently large security parameter, on the stated uniform exponent distribution, return g^(ab) in polynomial complete input time with success at least inverse-polynomial. A generic-group version may not use encoding-specific arithmetic. A representation-specific version must name the representation. Neither allowing Shor's quantum algorithm nor importing a CDH oracle answers the classical solver problem.

**Direct prior/current sources.** [Shoup, EUROCRYPT1997, publisher abstract](https://link.springer.com/chapter/10.1007/3-540-69053-0_18) was directly read: generic algorithms have matching square-root-type lower bounds in the largest prime factor. The author's revision link was authenticated from [his primary publication page](https://www.shoup.net/papers/); PDF extraction was incomplete, so no full-proof reread is claimed. A new generic polynomial solver cannot be admitted by ignoring this already stated lower bound.

[Maurer–Wolf, SIAM1999, author primary abstract](https://crypto.ethz.ch/publications/MauWol99b.html) was read. It distinguishes uniform/nonuniform results and displays a reduction complexity depending on nu(p), the minimum largest prime factor of an integer in a Hasse-type interval, plus an explicitly UNPROVEN smoothness hypothesis for the broad polynomial consequence. Therefore the book's compressed polynomial-reduction sentence is not used as a blanket unconditional theorem without restoring the primary hypotheses. The full48-page PDF did not extract completely; I do not declare a new textbook-error finding or certify every theorem of that paper.

The latest directly matched reduction primary located/read is [Bollauf–Parisella–Siim, *Revisiting Discrete Logarithm Reductions*, ePrint2025/1079](https://eprint.iacr.org/2025/1079),2025 abstract. It improves reductions for specified prime-order groups with somewhat-smooth p-1, including a concrete BLS12-381 statement, and distinguishes generic/algebraic models for extended assumptions. This is PRIOR scoped reduction work, not an unconditional classical CDH solver for every representation.

**Status/missing bridge.** No full representation-specific classical polynomial solver or general hardness proof was located in the dated2025–2026 search; this is an UNCERTIFIED search result, not proof of openness. Generic lower bounds and already-proved reductions are not fresh targets. The book does not isolate a new group family or reduction/resource theorem to attack. ## 4. DEC394 — nearest codeword is not list size, and two different “averages”

**Exact printed task.** Printed394 gives a finite-field linear [n,k] code C and y promised within Hamming distance t of C; find c in C MINIMIZING d(c,y). Its remaining open-looking sentence concerns average complexity, while it already records worst-case NP-hardness. Returning merely a codeword within t, a planted transmitted word, a short combinatorial list, or a new code construction is not automatically the exact nearest-codeword task.

**Formal target.** With a full-rank generator matrix G and code C=rowspan(G), output c* in argmin_(c in C)d(c,y) for every promised input (G,y,t). The worst-case polynomial solver is the already NP-hard general problem. For an average-case target one must also fix q,k(n),t(n), an input ensemble and success/runtime criterion. For example an explicit DERIVED ensemble could sample full-rank G uniformly, message m uniformly, and error e uniformly among weight-t vectors, then set y=mG+e; the required output would still be a NEAREST codeword, not necessarily the planted mG. This example is a possible modelling choice, not one prescribed or selected by the book.

**Current primary scope.** [Khesin et al., *Average-Case Complexity of Quantum Stabilizer Decoding*, ePrint2025/1769](https://eprint.iacr.org/2025/1769), abstract directly read, states that random CLASSICAL linear-code decoding at constant rate is widely believed hard and that all known algorithms in that regime are exponential. Its new reduction concerns quantum STABILIZER decoding; it does not prove an unconditional classical average lower bound or solve the book's classical task. The ACM2026 venue link returned403; only the actually read ePrint abstract is used.

[Guruswami–Li–Singhal, arXiv2608.22663v1](https://arxiv.org/html/2608.22663v1),23-Aug2026, and [Yuan–Zhu, arXiv2609.01070v2](https://arxiv.org/html/2609.01070v2),14-Oct2026, were opened through their actual statements/introduction. These already-published claims are not new targets here. Crucially AVERAGE RADIUS averages distances among list elements; it is not EXPECTED DECODING RUNNING TIME over an instance ensemble.

**Status/missing bridge.** The printed average-complexity question remains ensemble-unspecified; no full exact computational resolution was found in this bounded search, not proof of openness. A bounded written-first bridge would fix a non-stale ensemble/parameter regime and prove an algorithmic reduction connecting an actual search procedure or computational lower-bound model to exact nearest-codeword recovery. ## 5. NET439 — objective frozen from the book's actual betweenness specialization

Printed441 discusses different deletion/spread objectives; they are not silently conflated with shortest-path betweenness.

For one precise reading, use a finite simple connected undirected unweighted G=(V,E), integer0<=k<=|V|, and

```
GBC_G(C)=sum_(ordered s!=t in V) sigma_st(C)/sigma_st,
```

where sigma_st counts ALL shortest s-t paths and sigma_st(C) counts those meeting C at least once. Endpoints count as meeting C in THIS frozen objective, matching the primary below.
